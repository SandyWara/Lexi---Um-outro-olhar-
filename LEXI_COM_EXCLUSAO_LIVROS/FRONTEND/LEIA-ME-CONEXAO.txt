LEXI - VERSÃO SOMENTE CONEXÃO (base: A3 LEXI FINAL)

MANTIDO: HTML/CSS/layout originais, login simulado, navegação, biblioteca demonstrativa e controles de áudio já presentes.
ALTERADO: conexão de GET /api/livros, filtros por título/autor/gênero, POST /api/usuarios e GET/PUT de preferências.

NOVOS: SCRIPT/api.js (cliente HTTP) e SCRIPT/cadastro-api.js (ação temporária do botão Cadastrar existente, via prompts).
MODIFICADOS: SCRIPT/dados.js, SCRIPT/pesquisar.js, SCRIPT/lexi.js (proteção para lista vazia), SCRIPT/preferencias.js, lexi.html (dois includes).

TESTES:
1. Abra a pasta em VS Code com Live Server; abra lexi.html.
2. Inspecione F12 > Console/Network. A API gratuita pode demorar a responder.
3. O catálogo deve consultar GET /api/livros. Se rota não existir, mostra erro e NÃO disfarça dados locais como se viessem da API.
4. Clique Cadastrar no cabeçalho e forneça DADOS FICTÍCIOS nos prompts; confira POST /api/usuarios. O idUsuario retornado fica no localStorage. NUNCA use uma senha pessoal para testar.
5. Abra Preferências e clique Salvar. Confira PUT /api/usuarios/{id}/preferencias, e recarregue para GET.

PENDÊNCIAS EXTERNAS: controller de livros ausente no ZIP do Back-end; confirmar se foi publicado. Login real /usuarios/login não consta no código recebido. Biblioteca/favoritos reais não possuem rotas no ZIP enviado.
IMPORTANTE: a tela Acessar continua simulada, como na original; cadastro não equivale a autenticação. NÃO tratar idUsuario do localStorage como login seguro.
ATENÇÃO: no Back-end recebido, POST /usuarios devolve entidade Usuario que pode incluir a senha; o Back-end deve corrigir isso e usar hash de senha antes de uso real.

OBS: não foi incluída uma nova tela de leitura, nem alterado o visual do projeto. A rota obterLivro está preparada em api.js para quando a equipe conectar a tela de leitura.
